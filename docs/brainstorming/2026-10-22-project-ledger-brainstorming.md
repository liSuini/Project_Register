# 头脑风暴记录：项目台账系统

> 日期：2026-10-22
> 主题：一个项目一本账 —— 项目全生命周期台账系统

## 一、项目定位

面向项目全生命周期的台账管理系统，以"项目"为核心实体，串联前向签约立项、后向采购实施、交付验收全流程，并将过程性资料、履约资料按环节归档。核心目标是"**一个项目一本账**"——项目从立项到交付的每一笔记录、每一份资料，都能在一个页面上完整、清晰地看到。

## 二、关键澄清结论（多轮问答收敛）

### 2.1 用户规模与部署
- **个人工具**：自己或 2-3 人使用，本机运行，SQLite 存储，**无需登录认证**，开发最快。

### 2.2 阶段建模
- **固定生命周期状态机**：商机 → 中标 → 签约 → 立项 → 采购 → 实施 → 交付 → 验收 → 结算。
- **补充**：历史存量项目可直接从任意阶段开始（不强求走完整链路），项目可在任意阶段创建并录入。

### 2.3 项目与明细的关系
- **项目 1 对多**：一个项目下可挂多笔采购订单、多笔交付验收记录，供应商也可多个。

### 2.4 环节与附件
- **环节多级递归**：阶段 → 子环节 → 附件，层级可嵌套（如采购阶段下多笔订单，订单内又可细分签约/到货/开票），附件可挂载到任意一级。
- **按环节归档 + 全局检索**：附件按所属环节自动归类；全局检索**暂时仅按项目名称**检索。

### 2.5 统计口径（三口径）
- **前向（签约）**：签约金额（项目主表）
- **后向（采购）**：采购金额（采购明细累计）
- **交付（回款）**：回款/到账金额（验收记录累计）
- 提供三张统计卡片 + **Excel 导出**。

### 2.6 技术栈
- **FastAPI + SQLAlchemy + SQLite** 后端，**Vue3 + Element Plus** 前端，本机单进程运行。
- 与用户既有 BidAlert 技术栈一致，开发维护成本最低。

### 2.7 存量数据
- **暂不导入**既有 Excel/系统，先把新系统建起来，后续按需补导入功能。

## 三、核心领域概念（初稿）

| 概念 | 说明 |
|------|------|
| Project（项目） | 主实体，含名称、当前阶段、签约金额、合同编号、客户、日期等 |
| Stage（阶段） | 生命周期状态机节点，状态字段，可含子环节（递归） |
| Node（环节/子环节） | 阶段下可嵌套的环节，任意层级，可挂附件 |
| Attachment（附件） | 文件记录，挂载到任意环节/项目，存储于本机文件系统，数据库记录元信息 |
| PurchaseOrder（采购单） | 项目下多笔采购明细，含采购金额、供应商 |
| AcceptanceRecord（验收记录） | 项目下多笔交付验收，含验收金额/回款金额、日期 |
