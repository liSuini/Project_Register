# 需求拆分：项目台账系统

> 日期：2026-10-22 ｜ 基于 PRD v0.1

## 拆分原则
- 每个模块可独立交付、可独立验证。
- P0=必须（核心台账闭环），P1=重要（统计与导出，属于验收），P2=可选（增强）。
- 依赖关系标注模块间的前置关系。

## 依赖拓扑
- 基础层：M0（数据模型）→ 之上可并行 M1/M4
- M1 → M2、M3、M6
- M4 → M5
- M2+M3 → M7 → M8
- 前端：M9 基础 → M10 依赖后端 M1/M4/M5；M11 依赖 M7/M8

## 建议实施顺序
1. **MVP（核心闭环）**：M0 → M9 → M1 → M4 → M5 → M10
2. **明细与统计**：M2 → M3 → M6 → M7 → M8 → M11
3. 全部完成后再统一联调与收尾。

## 交付口径
- 最小可用（MVP）＝ M0/M1/M4/M5/M9/M10：创建项目、阶段流转、环节树、附件归档、项目详情页。
- 完整版 = MVP + M2/M3/M6/M7/M8/M11（采购、验收、检索、统计、导出）。
