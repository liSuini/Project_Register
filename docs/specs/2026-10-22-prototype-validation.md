# 原型验证文档：项目台账逻辑原型

> 日期：2026-10-22 ｜ 验证方式：逻辑原型（单文件 HTML，内存态，throwaway）
> 原型存档：分支 `prototype/ledger-logic-v1`（docs/prototypes/ledger-logic-prototype.html），本地即时体验副本：`.temp/prototype/ledger-logic-prototype.html`（双击即开）

## 验证的问题

**状态模型是否顺手**：阶段锚点树 + 独立当前阶段字段 + 三口径聚合的组合设计（ADR-0002/0004 核心），用真实交互跑一遍是否成立。

具体验证点：
1. 存量项目从任意阶段起步的语义（起始前的阶段标"存量未纳入"）
2. 阶段自由流转：推进、跳转、回退是否自然；回退时资料树是否保持不动
3. 9 锚点自动生成；锚点不可删不可改名
4. 子环节任意嵌套 + 附件挂任意层级
5. 非空节点（有子环节或有附件）删除保护，拒绝信息是否清晰
6. 三口径实时聚合（签约额来自项目主表、采购额/回款额=Σ明细，只算不存）
7. 附件挂在环节上的归属语义（原文件名展示 + uuid 物理名）

## 验证方法

- 浏览器自动化执行 5 个引导场景 + 状态断言（内存 state dump 逐项核对数值）+ 事件日志核对拒绝路径。
- 场景矩阵：①存量从"采购"起步 ②新项目从"商机"起步逐步推进 ③验收打回实施（回退） ④采购锚点下建子环节→挂附件→再嵌套→尝试删除（应拒） ⑤加采购/验收观察三口径联动。

## 沉淀的决策（合入主分支的部分）

1. **非空禁删语义确认**：删除顺序约束为"先清子环节和附件，再删节点"，锚点永不可删——比"级联删除带确认弹窗"更安全，符合资料保护优先。
2. **起步前置阶段标记为"存量未纳入"**（不隐藏、可点击流转）：既保留历史痕迹，又不阻断后续编辑——存量项目语义最终定版。
3. **回退即纯状态变更**：阶段回退绝不触碰环节树/附件/明细，这条不变量写入 service 层测试。
4. **三口径卡片显示"有数项目数"**（如"有采购单项目 N 个"）而非全部项目数，口径更清晰。
5. 金额单位交互展示用"万元"（贴合台账用户习惯），数据库层仍按设计存"元"，前端展示层换算。

## 遗留微调项（不阻塞，编码期吸收）

- 原型中"未纳入"阶段仍可点击流转（灵活优先）；生产版在未纳入阶段点击时给一次性提示但允许（保持 FR-4 自由流转语义）。
- 附件删除与节点删除的联动提示文案，生产版用 409 错误码 + 前端 toast 呈现。
