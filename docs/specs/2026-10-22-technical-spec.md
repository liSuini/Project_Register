# 技术规格：项目台账系统（Technical Spec）

> 日期：2026-10-22 ｜ 上游：PRD v0.1 · CONTEXT.md · ADR 0001-0004 · 架构设计
> 术语遵循 CONTEXT.md：项目/起始阶段/当前阶段/环节树/阶段锚点/子环节/附件/采购单/验收记录/三口径

## Problem Statement

用户（商机签约组的个人台账管理者）目前缺少一个把项目"前面怎么签的、后面怎么采的、最后怎么交的、资料都放哪了"聚在一处的工具。现状是：签约信息在合同系统、立项在 ICT 管理列表、采购在采购群、验收资料散在微信/邮箱，需要汇报或对账时四处翻找、手工拼接 Excel，历史存量项目更是无从下手。痛点本质：**没有一个项目一本账**。

## Solution

本机运行的个人工具（无需登录）：以项目为主实体建立台账，创建项目时自动生成 9 个阶段锚点（商机→中标→签约→立项→采购→实施→交付→验收→结算）构成归档树骨架；历史存量项目可从任意阶段起步；当前阶段独立流转可推进可回退；子环节任意嵌套、附件挂任意层级实现按环节归档；采购单与验收记录作为项目平级明细支撑三口径统计（签约额/采购额/回款额），统计页三卡片 + Excel 一键导出；全局按项目名称检索。

## User Stories

1. 作为项目管理者，我想创建项目并选择起始阶段，以便首个动作就把存量或新项目录入台账而非被迫从商机开始。
2. 作为项目管理者，我想在创建项目时填写名称、客户、合同编号、签约额、负责人、起止日期、备注，以便台账一建立就携带完整前向要素。
3. 作为项目管理者，我想项目创建后自动出现 9 个阶段锚点，以便无需手工搭架子、资料天然按阶段分区。
4. 作为项目管理者，我想看到当前阶段高亮的阶段步进条并可直接点击流转，以便一眼知道项目走到哪、一秒推进到下一站。
5. 作为项目管理者，我想阶段既可以推进也可以回退，以便纠正误操作或项目实际回炉（如验收打回实施）。
6. 作为项目管理者，我想每次阶段流转都留痕，以便回溯项目节奏、汇报时有据可查。
7. 作为项目管理者，我想在项目下新增多笔采购单（名称、供应商、金额、日期、备注），以便后向采购按笔登记而非一笔烂账。
8. 作为项目管理者，我想编辑和删除采购单，以便修正错录。
9. 作为项目管理者，我想在项目下新增多笔验收记录（名称、验收日期、回款金额、备注），以便交付回款按笔登记。
10. 作为项目管理者，我想采购明细表和验收表在详情页实时累计金额，以便打开详情即知采购额与回款额。
11. 作为项目管理者，我想给项目按名称模糊检索，以便台账多了之后秒级定位。
12. 作为项目管理者，我想按当前阶段筛选项目列表，以便盯住同一阶段（如所有待立项）的项目批量推进。
13. 作为项目管理者，我想查看统计页三口径卡片（前向签约等）——项目数+合计金额，以便给领导报数不用手工加总。
14. 作为项目管理者，我想导出三口径明细 Excel，以便报表直接外发、脱离系统也能对账。
15. 作为项目管理者，我想在阶段锚点下创建子环节并可继续嵌套，以便把"采购"拆成逐笔订单环节、"实施"拆成里程碑。
16. 作为项目管理者，我想重命名、删除子环节，以便过程记录随业务实际调整。
17. 作为项目管理者，我想删除有内容（子环节或附件）的环节时被系统拒绝并得到明确提示，以便防止误删整棵子树连带资料丢失。
18. 作为项目管理者，我想给任意层级环节上传附件（合同扫描件、验收单、过程资料），以便履约资料随环节归档而非堆在文件夹。
19. 作为项目管理者，我想下载和删除已上传附件，以便资料的增删与线下取用。
20. 作为项目管理者，我想打开项目详情页就看到完整一本账（概要+阶段+树+明细+附件计数），以便零跳转完整审视项目。
21. 作为项目管理者，我想附件上传时保留原始文件名作为显示名，以便在系统中能看到"XX合同.pdf"而不是乱码存储名。
22. 作为项目管理者，我想在本机 localhost 访问整个系统，以便无需部署、双击脚本即用。
23. 作为项目管理者，我想数据库与附件目录直接拷贝即完成备份，以便数据安全可控。

## Implementation Decisions

- 单仓库两目录：`backend/`（FastAPI + SQLAlchemy + SQLite）与 `frontend/`（Vue3 + Vite + Element Plus）；理由与锁定期见 ADR-0001。
- 分层：`api/` 路由为薄适配层（只做参数校验与委托）；全部行为在 `services/` 深模块内（project_service / tree_service / stats_service / storage / 采购与验收明细服务）。
- 阶段建模遵循 ADR-0002：9 个阶段为常量集合（商机、中标、签约、立项、采购、实施、交付、验收、结算）；当前阶段是 projects 表上的独立字段，流转写 stage_history；环节树顶层为随项目自动创建的 9 个阶段锚点（nodes.parent_id 为空、带 stage_key），锚点不可删不可改名。
- 环节树遵循架构设计：nodes 自引用递归，子节点保证与父节点同 project_id（防跨项目挂载）；非空节点（有子节点或有附件）删除返回 409 状态冲突。
- 附件遵循 ADR-0003：文件落 `data/uploads/{project_id}/{uuid}{ext}`，数据库只存元数据（original_name/stored_path/size/mime/uploaded_at/node_id）；物理名 uuid 防路径注入，原名仅展示。上传顺序：先存文件成功再写库记录（不留孤儿记录）；删除顺序：先删记录再删文件，物理文件缺失时不报错。
- 采购单/验收记录为项目平级明细（ADR-0004），金额非负校验（允许 0）；三口径中采购额=Σ采购单金额、回款额=Σ验收记录回款金额，只算不存、不冗余到 projects。
- 一账详情聚合接口 `GET /api/projects/{id}/ledger`：项目+树（含附件计数）+采购+验收一次返回，前端详情页单请求渲染。
- API 契约与统一错误 `{code, message}`：404 资源不存在 / 409 状态冲突（删非空节点）/ 422 参数非法，完整路由见架构设计文档第 4 节。
- 统计：`GET /api/stats` 返回三卡片（前向项目数与签约额合计、后向项目数与采购额合计、交付项目数与回款额合计）；`GET /api/stats/export` 用 openpyxl 生成三 sheet 明细流式返回。
- 阶段流转 `PATCH /api/projects/{id}/stage`：目标阶段必须在 9 阶段集合内，允许跳转与回退；from/to 写入 stage_history。
- 检索：`GET /api/projects?keyword=&stage=`，名称 LIKE 模糊 + 当前阶段精确过滤。
- 前端三页：ProjectList（检索/筛选/新建）、ProjectDetail（概要条+StageStepper+NodeTreePanel+采购验收双表）、StatsView（三卡片+导出）；电信蓝商务风、精简单表、忌过度分类。
- 配置：后端读取环境变量（数据库路径、上传根目录、跨域）；开发期 Vite 代理 /api 到 8000 端口。

## Testing Decisions

- 测试哲学：只测外部行为，不测实现细节；接口即测试面（codebase-design：callers 与 tests 跨同一接缝）。
- 单元测试打 services 接口（最高接缝，无新接缝引入）：
  - project_service：创建（任意起始阶段锚点自动生成 9 个）、检索（名称模糊/阶段过滤）、阶段流转全矩阵（含回退、含非法目标拒绝）、ledger 聚合完整性。
  - tree_service：加/删/改子环节、锚点保护（删/改名被拒）、跨项目 parent 校验、非空节点删除拒绝（409 语义）。
  - storage：存取删往返、物理文件真实存在与删除、缺失容忍、uuid 物理名与原名并存。
  - stats_service：三口径聚合（含空项目=0、多笔采购累计、验收累计）。
- 集成测试走 FastAPI TestClient（真实 HTTP 语义 + 统一错误契约）：一条全链路测试串起"建项目→锚点生成→建子环节→传附件→加采购验收→统计变化→导出能被 openpyxl 打开"。
- 前端个人工具体量：Vite dev 手工目检关键页面（列表检索、详情一账、统计导出），不铺 e2e。
- 无既有测试先例（全新仓库），本 spec 即测试基线。

## Out of Scope

- 登录认证、多租户、权限体系、操作审计日志（个人工具，ADR-0001 场景裁剪）。
- 存量 Excel/BPM 数据导入（PRD Non-Goal，待后续版本）。
- 统计图表可视化（本期仅数字卡片 + Excel 导出）。
- 与外部系统（BPM、ICT 立项系统）的实时对接。
- 消息通知、提醒、审批工作流。
- 多人并发写优化与行级锁（单机低频写，SQLite 写串行足够）。

## Further Notes

- 术语争议以 CONTEXT.md 为准（如"签约额"不是"中标金额"）；实现与术语冲突时改实现不改术语表，除非与用户重新澄清。
