# PRD: 项目台账系统（Project Ledger）

> 版本：v0.1 ｜ 日期：2026-10-22 ｜ 技术栈：FastAPI + SQLAlchemy + SQLite + Vue3 + Element Plus

## 1. Introduction / Overview

面向项目全生命周期的台账管理系统。以"项目"为核心实体，串联**前向签约立项、后向采购实施、交付验收**全流程，将过程性资料、履约资料按环节归档。核心目标是"**一个项目一本账**"——一个项目从立项到交付的每一笔记录、每一份资料，都能在项目详情页上完整、清晰地查看和管理。

本系统定位为**个人工具**（2-3 人使用），本机运行，无需登录认证。

## 2. Goals

- 以项目为主实体，完整记录固定生命周期：商机 → 中标 → 签约 → 立项 → 采购 → 实施 → 交付 → 验收 → 结算。
- 支持历史存量项目从**任意阶段**起步（不强求走完整链路）。
- 一个项目下可维护**多笔采购明细**、**多笔交付验收记录**（项目 1 对多）。
- 环节支持**多级递归**（阶段 → 子环节 → 附件），附件可挂载到任意层级并归档。
- 提供**前向/后向/交付三口径统计**（签约额/采购额/回款额）与 **Excel 导出**。
- 全局按**项目名称**检索。

## 3. User Stories

### US-001: 创建项目（支持从任意阶段起步）
**Description:** 作为用户，我想创建一个新项目并选择起始阶段，以便录入商机/存量项目。

**Acceptance Criteria:**
- [ ] 新建项目时必填项目名称、客户、起始阶段、签约金额（可选，按阶段）
- [ ] 可选择任意阶段作为起始阶段（默认"商机"），起始阶段之前的状态标记为不适用
- [ ] 项目创建后出现在项目列表
- [ ] 保存后可通过数据库/接口验证
- [ ] 前端页面渲染正常（Verify in browser）

### US-002: 项目生命周期状态流转
**Description:** 作为用户，我想要推进项目阶段，以便跟踪生命周期进展。

**Acceptance Criteria:**
- [ ] 项目详情页显示当前阶段，支持手动推进/回退到其他阶段
- [ ] 阶段流转记录操作时间，保留当前阶段字段
- [ ] 非起始阶段前默认不可达，但可手动调整（存量场景）
- [ ] 阶段变化反映在列表与统计口径中

### US-003: 采购明细管理（项目 1 对多）
**Description:** 作为用户，我想要在项目下维护多笔采购订单，以便登记后向采购。

**Acceptance Criteria:**
- [ ] 项目下可新增/编辑/删除采购单（采购名称、供应商、采购金额、日期）
- [ ] 采购明细列表在项目详情页展示，金额累计为项目采购额
- [ ] 项目采购额为统计口径（后向）

### US-004: 交付验收记录管理（项目 1 对多）
**Description:** 作为用户，我想要在项目下维护多笔交付验收记录，以便登记回款。

**Acceptance Criteria:**
- [ ] 项目下可新增/编辑/删除验收记录（验收、日期、回款金额）
- [ ] 回款金额累计供给交付口径

### US-005: 环节多级递归（项目 → 子节点 → 附件）
**Description:** 作为用户，我想要在项目下创建子环节并可继续嵌套，以便按业务细分登记。

**Acceptance Criteria:**
- [ ] 项目详情页展示环节树，节点可嵌套到任意层级
- [ ] 可新增/编辑/删除任意层级节点
- [ ] 每个节点都可挂载附件
- [ ] 数据结构支持递归（parent_id 自引用）

### US-006: 附件归档与上传
**Description:** 作为用户，我想要把过程性/履约资料挂到对应环节，以便按环节归档。

**Acceptance Criteria:**
- [ ] 任意环节节点可上传附件，文件存储到本机文件系统，数据库记录元信息
- [ ] 附件按所属环节自动归类（目录结构）
- [ ] 可下载/删除附件
- [ ] 项目详情页能按环节查看附件

### US-007: 全局检索（按项目名称）
**Description:** 作为用户，我想要按项目名称检索，以便快速定位台账。

**Acceptance Criteria:**
- [ ] 项目列表提供搜索框，按项目名称模糊匹配
- [ ] 无结果时显示空状态提示

### US-008: 三口径统计与导出
**Description:** 作为用户，我想要查看前向/后向/交付三口径统计并导出 Excel，以便汇报对账。

**Acceptance Criteria:**
- [ ] 统计页展示三张卡片：签约额(前向)/采购额(后向)/回款额(交付)
- [ ] 卡片含项目数、合计金额
- [ ] 支持一键导出 Excel（含明细）

## 4. Functional Requirements

- FR-1：项目主表记录：项目名称、客户、合同编号、当前阶段、起始阶段、签约金额、负责人、开始/结束日期、备注。
- FR-2：生命周期状态集合固定为：商机、中标、签约、立项、采购、实施、交付、验收、结算。
- FR-3：项目可从任意阶段创建；创建时若起始阶段非"商机"，则此前阶段标记为不适用（历史存量场景）。
- FR-4：项目当前阶段可手动推进或回退，不强制顺序（存量/跳跃场景需灵活）。
- FR-5：项目 1 对多维护采购明细（采购金额、供应商、日期）；采购额=采购明细金额之和。
- FR-6：项目 1 对多维护交付验收记录（验收日期、回款金额）；回款额=验收记录金额之和。
- FR-7：环节节点采用自引用递归结构（parent_id），可嵌套任意层级；每个项目有一个根环节树。
- FR-8：附件可上传到项目任意环节节点；文件存本机文件系统，数据库记录文件名、路径、大小、上传时间、所属节点。
- FR-9：全局检索按项目名称模糊匹配（LIKE）。
- FR-10：统计页提供三口径卡片（项目数 + 合计金额），支持导出 Excel 明细。
- FR-11：前端为单页应用（Vue3 + Element Plus），通过 RESTful API 与 FastAPI 后端交互。

## 5. Non-Goals（本期不做）

- 不做登录认证、组织架构、复杂权限、操作审计。
- 不做存量 Excel/系统数据导入（后续迭代）。
- 不做统计图表可视化（仅数字卡片 + Excel 导出）。
- 不做对外部系统的实时接口。
- 不做通知/提醒、工作流审批。

## 6. Design Considerations

- 前端采用 Element Plus，电信蓝商务风格、精简表单、避免过度分类（沿用用户既有偏好）。
- 项目详情页为"一页账"：上方项目概要 + 阶段树，下方三口径金额汇总 + 附件区。
- 附件上传使用本机文件系统目录（如 `data/uploads/`），按项目/环节建立子目录。

## 7. Technical Considerations

- 后端：FastAPI + SQLAlchemy + SQLite（文件库，单机适用）。
- 前端：Vue3 + Vite + Element Plus。
- 数据库表：projects、purchase_orders、acceptance_records、nodes（自引用）、attachments、stage_history（可选）。
- 项目当前阶段用冗余字段 `current_stage` 便于统计与列表展示。
- Excel 导出可用 pandas/openpyxl 生成 .xlsx。
- 单机本地运行，默认 `http://localhost:8000`（后端）+ Vite dev（前端）。

## 8. Success Metrics

- 一个项目全流程记录（签约/采购/交付）可在单一详情页完整查看，无跳转遗漏。
- 从创建项目到挂载第一批附件 ≤ 5 次点击。
- 三口径统计值能由明细自动汇总、口径一致。
- Excel 导出可直接打开使用。

## 9. Open Questions

- 阶段树是否需要允许在多个阶段之间自由跳转（如从"签约"直接到"交付"）？默认允许，灵活优先。
- 是否需要为采购/验收记录绑定到具体环节节点，还是作为项目平级明细？默认作为项目级明细（独立于环节树）。
- 附件是否需要断点/类型限制（如仅 PDF/图片）？默认允许常见办公文件，不做强校验。
